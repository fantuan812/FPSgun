## 3. Unified phase ordering (not enemy-array order)
Existing primary firing, mortar/hazards, each ordinary AI/movement/clamp, spawn_requests, hostile and friendly projectile updates, deaths/kill events and pickup events retain their mutual order.

Support movement occurs in the normal enemy loop: in move state seek desired player distance using ranged +/-30 deadband; warning and recover stationary. Clamp/sprite/actor observation continue as normal. It never produces an offensive AI event. Existing contact convention remains: move contact hurts, warning/recover contact-safe. Only support-specific branch differs.

Phase A occurs once AFTER all existing enemy AI/movement/clamp and queued child spawning, BEFORE hostile projectiles. All sources/targets use these current post-clamp positions. Traverse living support sources in ascending ID. All support sources snapshot membership at Phase A; later additions cannot acquire this step. Main mode spawn occurs before CombatRuntime.step and is included; existing queued summons are parented and ineligible. No new extra spawn requests.

For an existing warning, first validate recipient/source/range and source HP witness; cancel if invalid. Otherwise decrement warning_left by dt once, and mark due if <=0. For a nonwarning source, decrement cooldown once; if <=0 attempt acquisition. If acquired set warning_left=1.2 and snapshot source HP, and DO NOT subtract this step's dt from newly started warning. If none eligible set cooldown=retry1s, remain move. No looping/catch-up, at most one completion per source per step.

Existing damage before acquisition (primary firing, mortars, hazards, hostile contact proc during older AI) is already reflected in start HP and does not retroactively interrupt. Existing warning source HP is compared to its original snapshot, so those same early paths DO interrupt an ongoing channel. Late projectile/proc loss after acquisition interrupts even in acquisition's own step. This discrete phase boundary is intentional, not a continuous time/subframe claim.

Phase B occurs once AFTER all existing pickup/proc handling and flash aging, BEFORE final focus prune. If session.state!='playing', do not heal, cancel any support channel and hide its tether. Re-find source and target by ID; membership alone is insufficient: both must hp>0 even if a late kill/proc left a dead Dictionary not yet removed. Recheck eligibility, current endpoint distance, and source HP witness for EVERY active warning, including not-yet-due channels. Invalid cancels immediately. A target reaching full HP invalidates/cancels rather than reserving repair. Valid due intents resolve in ascending source ID; each rechecks after previous repair. Apply min(max_hp,hp+10), no other mutations of target attack/status/reward/maxHP. If earlier source fills target, later one cancels, no stored charge.

Do NOT repeat or flush the old death loop after repair: existing reward/drop timing remains. Dead-at-end actors never resurrect. Pickup/kill procs that kill source/target in this step beat repair. Terminal early returns in older runtime paths likewise prevent Phase B healing. Direct invocation on a nonplaying frame may not execute new support phases/heals, without asserting changes to unrelated legacy direct-step behavior.

## 4. Cancellation/cooldown/large dt
Damage interruption is source.hp < channel_start_hp, not hit/VFX count. The source cannot receive any new healing; baseline inventory finds no other enemy HP increase. No signal hooks or damage rewrites necessary. Target nonlethal loss alone does not interrupt. Zero resolved damage, chill/slow alone and pure pull/push do not damage-interrupt; displacement may independently fail range at Phase A or B. No continuous path-crossing test between those observations.

Success or cancellation at Phase A/B enters recover for .7s and sets cooldown5s at that exact phase. No subtraction from newly set cooldown/recovery until next tick. Recovery countdown and cooldown advance once on later Phase A ticks; once recovery expires movement resumes on the next normal movement pass. Cooldown is measured from actual success/cancel, not acquisition. Cancel at A cannot reacquire that tick. Large dt can expire a pre-existing warning once but cannot begin a second channel or catch up cooldown during the same tick. Valid dt is existing simulation nonnegative finite input; focused tests include0, exact1.2 expiration and large dt, without relaxing generic runtime contracts.
