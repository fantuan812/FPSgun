## 1. Actual gap and one bounded decision

`main.gd::_input` has movement-related controls elsewhere, Escape/I and upgrade keys but no combat mouse/target command. The title explicitly advertises nearest-target auto-fire. `WeaponCombat.fire` takes the first living nearest actor with strict `<` comparisons for Rivet, Shotgun, Rail, Return and Mortar; Cryo and Bankshot use `Status.ordered_living` (distance then numeric ID). Orbit is a radial sweep. `BoundaryShot._guide_direction` is autonomous first-boundary redirection, not player-selected priority. `_sync_weapon_rig` separately uses the old first-nearest target for every idle mount.

A nearby crawler therefore diverts aimed attacks from a farther Spitter, Broodkeeper or mandatory boss until movement changes proximity. Add one optional priority mark: **left-click near a living enemy's center (inside its pick disk) during play to mark its current ID; left-click empty valid playfield to return to AUTO.** This is acquisition preference, not free aim, guaranteed damage, manual firing or a homing upgrade. Prioritizing a remote threat can leave closer threats alive. Actual collisions and each weapon's range still apply.

No new weapon/module, catalog/profile row, art asset, economy, damage multiplier, cadence, enemy, encounter, save/account/network/audio/dungeon system or controller binding. Existing physical keyboard movement/dash and automatic firing remain. No performance, balance, fun, all-seed or universal survival guarantee follows from prior full-run proof or this feature.

## 2. Input, transform and exact picking

- Only an **unhandled** `InputEventMouseButton`, `button_index == MOUSE_BUTTON_LEFT`, `pressed == true`, in `state == "playing"` may select or clear. Do not poll held buttons, handle mouse motion/release, or add targeting to the pre-GUI `_input` handler. A repeated press on the already selected actor is idempotent, not a toggle. Other buttons/keys retain their old behavior.
- GUI-consumed events must never reach selection. Additionally reject positions inside the measured visible HUD rectangle, visible boss-panel rectangle, and visible mode/objective text/badge bounds, even though some presentation nodes intentionally ignore mouse input. Modal-visible or non-playing states reject. Thus clicking HUD text/bars/buttons, the priority caption itself, menus, a modal close/resume/start button or an enemy behind those rectangles never silently selects/clears.
- Use the incoming event's `position` in its Viewport coordinate space, not the live mouse position, desktop/window coordinates, a hard-coded scaling ratio or a guessed camera center. Require a finite point inside `get_viewport().get_visible_rect()` (Rect2 top/left inclusive; bottom/right exclusive). Convert with the main CanvasItem's `make_canvas_position_local(event.position)` (equivalently inverse `get_global_transform_with_canvas`). Reject nonfinite/noninvertible transforms and nonfinite results. The current canvas/camera transform must be used once; do not apply window stretch twice.
- Converted position must lie in the actual arena field rectangle `[0,width) × [0,height)`. Outside-field clicks, outside viewport, letterbox/pillarbox and invalid inputs do nothing—not even clearing an existing mark. Actual960×540,1280×720 and letterboxed1180×812 behavior must be verified, not inferred from this formula.
- Each pick candidate is a current living enemy Dictionary with an actual positive integer `id`, finite positive HP, finite Vector2 `pos`, and finite positive numeric `scale` (not bool). Invalid entries are ignored, never repaired. The computed radius, radius squared and click-to-center squared distance must also be finite and the radius positive; overflow/nonfinite intermediates reject that candidate rather than becoming an always-hit disk. A valid click point is inside its **closed** pick disk iff squared center distance `<= (16.0 * scale + 8.0)^2`. The8-world-unit padding affects selection only; it never changes damage collision, reach, sprite size or enemy physics.
- If disks overlap, choose the smallest exact squared distance from click to center, then the smallest integer ID on an exact distance tie. Do not use approximate tie merging, array order, normalized distance, highest HP, boss/type guesses or random draws. The intersecting on-viewport portion of a partly clipped actor's pick disk may be selected; no point outside the valid viewport can pick it.
- A valid playfield press with no candidate sets AUTO (`0`); pressing the same candidate, or empty ground while already AUTO, is a no-op. Invalid requests do not become empty-ground clears. No queued/deferred entity-ID callback is introduced: each click resolves current geometry/current live IDs.

Official Godot4.6 references supporting the coordinate/input choice: [mouse event position](https://docs.godotengine.org/en/4.6/classes/class_inputeventmouse.html#class-inputeventmouse-property-position), [CanvasItem viewport-to-local transform](https://docs.godotengine.org/en/4.6/classes/class_canvasitem.html#class-canvasitem-method-make-canvas-position-local), [unhandled input after GUI](https://docs.godotengine.org/en/4.6/classes/class_node.html#class-node-private-method-unhandled-input), and [stretch/aspect settings](https://docs.godotengine.org/en/4.6/classes/class_projectsettings.html#class-projectsettings-property-display-window-stretch-aspect). These docs are design support, not executed input proof.

## 3. Transient authority, lifetime and atomicity

- One transient `combat.focus_enemy_id` integer, default0=AUTO; positive values refer only to the existing monotonically assigned live enemy ID. No mutation/addition to build/catalog/enemy/projectile dictionaries merely to mark a target. No persistence or inferred next target by type/name/index.
- Selection/clear may change only this focus state and its derived presentation. No RNG access, clocks/rig age, firing/animation event, build revision, shop/choice generation, offers/reservation, money/fraction/XP/level, HP/dash/hurt, damage/status/proc counters/ICDs/effects, hazards, bullets, pending blasts, actor positions or encounter timing. No action spends a cooldown or fires immediately.
- Read-only views/helpers must not mutate or repair state; a dead/missing focus may display AUTO immediately without writing authority during inspection. Authoritative pruning belongs to shared combat-step/lifecycle boundaries. A stored ID that no longer resolves to a valid living enemy is ineligible for acquisition immediately; later weapon slots in the same combat step fall back if an earlier slot kills the focus, even before the existing death-removal pass.
- Prune dead/removed/invalid focus before a subsequent rendered frame and before further acquisition can treat it as live. Do not automatically reassign to another enemy. Clear on encounter settlement, room-clear entry, title, fresh run, same/new-seed retry, death and victory; reset before IDs can be reused in a new run.
- Merely moving beyond one/all weapon ranges, or moving off-screen, does **not** clear a living mark. Returning into range makes the preference eligible again. Pause, inventory, settings/codex reached from pause and mid-encounter upgrade choices preserve focus while simulation is paused; all selection inputs there are ignored, not queued. The cue may be hidden while a modal is open and reappear on resume. Existing application-focus loss still pauses without clearing focus; a click merely returning window focus must not resume play or select through the pause modal.

## 4. Per-weapon acquisition and exact compatibility

- A pure shared focus eligibility helper may find the current living ID and check that weapon's existing `Rules.weapon_reach` from current derived stats. It must not replace the existing nearest algorithms. The no-focus path remains the old path; no new sort/order, rounding, tolerance, RNG or timer normalization.
- Rivet, Shotgun, Rail, Return and Mortar: prefer the focus only if within the old strict distance boundary (`distance <= reach`). Otherwise execute the unchanged living-array first-nearest loop (`<`, not `<=`) and its existing reach rejection. Exact equal-distance array-order ties remain unchanged.
- Cryo and Bankshot: retain `Status.ordered_living`, its exact distance-then-ID ordering and existing reach tolerance `Status.DISTANCE_EPSILON` (0.0001). Choose the focused member of that already eligible set when present; otherwise take the original first member. Never add a larger range margin or normalize this path to the standard weapons' strict boundary.
- Cryo changes only cone orientation. The existing ordered victim iteration, cone inclusion, primary/brace resolution, chill-surviving-target timing and effect order remain unchanged. Do not move the chosen focus to the head of the damage iteration.
- Orbit remains completely radial: same presentation/fire direction, victim iteration, geometry, damage, cadence and effects; it ignores priority. The seven directional types may prefer the same ID independently, but a short-range copy falls back while longer-range copies prefer the mark. No shared maximum-range eligibility grants a short weapon extra reach.
- Preference affects only each future acquisition/aim. Existing bullets continue their stored trajectory and can hit/intercept other enemies first. Mortar stores the chosen current position at launch, not a tracking ID. Return's outbound shot and existing player-homing return remain unchanged. Bankshot initial aim may prefer the mark, but boundary reflection, first-boundary Bounce Guide targeting, quotas, paths and contacts do not inspect focus. Already launched shots/blasts never retarget when focus changes/clears/dies.
- Arc/Echo/Phase/Fracture/Feedback/hazards/mines/other secondary targeting and proc rules do not inspect focus. All damage formulas, tempered per-copy damage, v32 brace origin/direction rules, snapshots, hit/kill attribution and cadence remain unchanged. Choosing a frontal braced target does not bypass its defense. New aimed outcomes may naturally change hits/kills/procs; exact post-input encounter/RNG equality is not promised.
- Existing direct `WeaponCombat.fire(id,slot)` calls remain usable. No focus(default0) preserves old compatibility behavior, including tempered lookup fallback for mismatched/out-of-range slots. Focus is a world acquisition preference, not ownership metadata and not permission to change damage from another slot.

## 5. Rig and clear non-danger presentation

- The actual acquisition pose already uses `WeaponPresentation.fire`; preserve that pipeline. For idle rigs, keep the exact legacy `_sync_weapon_rig` call and common first-nearest target when AUTO. With a live mark, optional per-slot idle overrides apply only to eligible directional copies, using the same focus eligibility/range rule; every ineligible copy and Orbit retains the existing common idle target. Existing callers of `WeaponRig.update_poses` without overrides behave identically.
- No clearing/rebuilding/reordering the rig, resetting recoil/aim age/visible clock/generation, or rewriting historical `last_shot` merely on focus changes. In-flight Return visibility and Mortar visuals keep their old rules.
- Static four-corner brackets identify the currently living marked enemy, without a filled disk, orange hazard ring, pulsing/flashing effect or gameplay collider. Use a pale neutral/mint cue distinguishable by **shape and text**, respecting reduced-flash presentation. Brackets follow current actor position and naturally clip off-screen; no minimap, off-screen arrow or new art asset.
- Add a compact second line within the existing mode/objective area only while focused: target name, `eligible / directional owned copies in range`, and `click ground: AUTO`. Count copies independently using current per-weapon reach; exclude Orbit. This is range eligibility, not ready-cooldown count, guaranteed hit, DPS or line-of-sight certification. A radial-only loadout explicitly says its aim is unchanged instead of suggesting Orbit obeys the mark.
- Preserve the original objective's first line, combat HP/XP/dash/mechanics HUD and boss bar. No new opaque playfield panel or camera/layout change. Empty focus keeps the old objective/idle rig presentation; title/pause control help must explicitly say **click enemy CENTER** / click empty ground for AUTO and explain per-weapon fallback/Orbit exception. The padded pick disk is not a pixel mask and may be smaller than large boss art; never promise every visible sprite pixel is clickable. Actual native checks must establish that the two-line text fits and the cue is not confused with warning geometry at both modes/sizes/letterbox.
