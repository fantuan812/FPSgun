# v20 — combat HUD readability

The v19 exported Arena run exposed an inherited problem: the opaque bottom-wide boss status panel covered the player and a large part of a live Warden blast warning near the lower boundary. The upper opaque HUD could similarly mask actors. This increment addresses UI composition only; it does not move the playable boundary or camera, shrink hazard geometry, change hit damage, or replace artwork.

- Boss status uses no filled full-width backplate. Compact outlined name/phase/HP and exact attack hint share a row, with a four-logical-pixel translucent HP line below. Dead bosses still clear and two-live-boss controlled stress remains supported.
- The combat HUD's broad backplate is translucent. Combat labels have dark outlines, and combat bars/buttons no longer draw fully opaque blocks over the playfield.
- Modal, shop, inventory and settings panels retain their established opaque styling and input behavior.

Acceptance is bounded by the final independent report in `validation/independent-v20`. A 265-check focused layout/style test and both author/independent cold 60-entry suites plus import pass. A 1,600-step-per-build baseline/candidate comparison has identical authority traces for Arena/Rooms and Warden/Core, including real hit calls and actual charge/blast/ring/summon states. Its explicit boundary-position setup is controlled, not an ordinary GUI playthrough. The actual native baseline/candidate matrix covers both modes and 960×540, 1280×720 and 1000×750 windows (24 cases per build). An ordinary-control run of the exact new exported PCK separately reaches the live Warden lower edge and verifies the visible player/blast arc, upper traversal, menus, focus pause and purchase/deploy; brief Rooms startup/combat is also observed. Offscreen camera/world-edge clipping remains. This is not a complete v20 campaign or death/retry acceptance; headless rectangles are not GUI evidence.

The prior v19 runtime packages remain historical and do not acquire this UI fix retroactively. New runtime artifacts have their own exact fingerprints and bounded native Linux checks. A manual v19→v20 PCK update requires the documented original v19 hashes and a backup before replacement; full v20 archives are retained for recovery/new installations. Windows execution and audible audio remain unvalidated without an appropriate authorized host/device.
