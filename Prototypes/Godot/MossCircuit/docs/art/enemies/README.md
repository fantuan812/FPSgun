# 敌人与 Boss 九帧素材（2026-10-22）

本批使用内置 image_gen 生成六种原创角色，并逐张检查、再次用 image_gen 增加格内透明留白。没有用代码重绘、缩放或改写源 PNG。crawler 沿用已有甲虫。

| ID | 轮廓 | 实际九帧内容 |
|---|---|---|
| crawler | 锈色圆背甲虫 | 行走 |
| charger | 琥珀低伏独角犀牛机 | 四足行走 |
| spitter | 青紫圆炮口虫 | 短足行走 |
| flanker | 蓝色细长刀足蛛 | 刀足交替移动 |
| brood_keeper | 苔绿蜂巢背囊 | 行走与背囊轻微起伏 |
| boss_warden | 双重臂方形守卫 | 轻微机械机体脉动 |
| boss_core | 环形悬浮反应堆 | 核心脉动、悬缆摆动 |

攻击、召唤、冲锋及危险区是程序化预警/行为，不是另外绘制的九帧攻击动画。源帧有真实姿态变化，但仍是生成式动画原型；细节存在逐帧漂移，未宣称达到逐像素手工动画质量。

## 接口与复验

- `assets/enemies/enemy_manifest.json` 为唯一映射：`enemies[id].path`、`grid`、`frames`。
- region = 整图绝对 `[x,y,width,height]`；alpha_bbox = 格内 `[x,y,width,height]`，不是右下角坐标。
- 3×3、行优先；切片边界采用 `floor(column * width / 3)`，兼容旧甲虫非整除尺寸。
- 边界按 alpha **>8/255** 量测。生成 PNG 存在 alpha=1 的近透明噪声，直接 `get_used_rect()` 会把透明留白误算进角色边界；必须使用 manifest bbox 或同阈值计算。
- 源图不改动。用 AtlasTexture.region 选中角色，用 margin 对齐公共画布水平中心及脚底。角色视觉尺寸应按可见 bbox 高度而非整格留白计算。
- UI 头像直接使用第一帧可见 bbox。各角色名字、可见范围、每格哈希和源哈希均在 manifest。
- `python docs/art/enemies/validate_atlases.py` 只读取 PNG、重新生成元数据，不修改图像。依赖 Pillow。
- 本次验证：7张图、63格非空且各图九帧字节哈希互异；alpha>8边界均与格边分离。新增六图最小安全余量56–104px。哈希互异不等于动画质量保证，因此另逐张肉眼复核轮廓、步态与边界。

## 生产边界

这是高分辨率、像素风启发的生成素材，并非严格统一64×64或固定调色板的原生像素画。使用nearest过滤；没有声称逐像素网格严格一致。九帧循环最后一帧到第一帧仍可能有轻微机械细节跳变；正式美术替换应在固定低分辨率画布上手工清理。

`provenance.json` 保存初始提示词、布局修正提示词、生成工具和最终源路径；最终源PNG已完整复制入项目，外部工作目录路径不是运行依赖。源文件SHA256保存在manifest中。未复用商业游戏角色或受限素材。
