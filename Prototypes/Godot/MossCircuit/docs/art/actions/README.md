# v7 角色动作图集

2026-10-22 内置 image_gen 根据既有 hero_walk、boss_warden、boss_core 角色参考生成六张透明 RGBA 九帧原画。PNG 原样保留，没有 Python 绘画、缩放、抠图或像素重写；prompts.json 保存原始意图、最终修订提示及生成路径。不是概念图，action_manifest.json 给实际可运行 AtlasTexture region。

## 本批真实覆盖

- hero_attack：抬枪→开火→后坐→恢复。自带小手枪是通用射击姿态，不代表所有武器专属持械原画。
- hero_hurt：后仰→踉跄→恢复。
- hero_death：膝部失力→侧倒→熄灯；非循环，末帧保留身体。
- hero_dash：蓄势→低身前冲→恢复；原画不负责世界位移。
- boss_warden_attack：双拳抬起→下砸→触地→恢复。
- boss_core_attack：环片打开、线圈充能→局部能量脉冲→恢复。

五类普通敌人的其余受击、死亡、蓄力/释放反馈由主程程序化复用提供，本目录**没有**为每种普通敌人额外画九帧。也没有承诺所有武器姿态、全方向动作或各 Boss 所有技能均有独立图集。

## 非破坏切片和锚点

源图 1254×1254、视觉3×3排版。生成器未严格遵守三等分行的基线，直接按418×418切会切脚。因此 manifest 用统一 **418×340** 固定画布，每整行共同平移源 y 窗口到实际基线；不是每帧包围盒重新居中，不是逐帧缩放，也没有修改源 PNG。所有动作 anchor=(0.5,328/340)。reference_height 是该动作第一帧站立高度，整个动画保持同一缩放比。alpha_bbox 仅用于校验。

运行必须采用 manifest 的 region 而非自行三等分。所有动作保留源帧0..8顺序；hero_attack 第3帧开火（零起算），release_frame=3；boss_warden_attack 源第5帧触地，release_frame=5；boss_core_attack 第4帧脉冲，release_frame=4。伤害调度由主程同步，不能视图动画每次重放又重复造成伤害。准确预警仍用游戏几何。

## 美术验证与边界

逐张实看：角色身份保持苔绿装甲、米白面罩/黄眼及背包；守卫保留双拳与锈橙不对称装甲；核心保留黄铜环、绿核和紫线圈。动作是肢体变化，不是九张移动立绘缩放。首版 hero_attack 超格、warden跨行及death脚部贴边已通过重新生成并元数据取窗解决，所有最终取窗包含角色且无相邻行污染。

validate_assets.py 只读验证54帧非空、各动作9帧像素互异、尺寸/源SHA256、真实透明背景与alpha>8内容边距至少8px（本次实测最小12px），检查全部通过。build_manifest.py 只读图像生成元数据，不写PNG。

如实限制：高分辨率像素风，不保证严格低分辨率统一像素网格；AI局部细节和脚部仍有小幅漂移。几何测试不能替代窗口内连贯性、人类试玩或Windows验证。此批没有声称GUI实机通过。受击与死亡动画不能改变玩法无敌时间/死亡结算，具体生命周期、暂停/重置由主程及独立QA验证。
