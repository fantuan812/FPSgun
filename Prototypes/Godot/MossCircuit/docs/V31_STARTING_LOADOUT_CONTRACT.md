# v31 starting-loadout contract — frozen scope

## Scope and data
- Add one pre-run decision: choose a starting loadout. This is the same hero, not a character/class/unlock system. No new weapon, module, stats, art, save, account, mode, encounter or balance-rule changes.
- Shipped ordered registry `data/starting_loadouts.json`: `rivet` / Rivet Starter = one `rivet_gun` +35 scrap; `scatter` / Scatter Starter = one `scrap_shotgun` +23 scrap; `rail` / Rail Starter = one `rail_lance` +17 scrap. No modules, upgrades or hidden modifiers.
- Scrap values are explicit fixed data, not calculated from mutable shop prices. Current weapon purchase price plus scrap is59 for each; this is a tuning rationale, not equal-power/balance certification. Selling a starting weapon follows existing resale rules, with no special refund.
- Rivet remains cold-launch default and exact old build initialization. Keep `Rules.new_build(catalog)` unchanged. A separate pure starting-loadout helper validates registry, looks up detached rows and creates a new build through the existing factory; alternative kits change only initial weapon ID and integer coins. Revision0, fraction0 and all other fresh-build fields remain the factory values.
- Registry version1; nonempty ordered loadout array with at most8 rows; unique nonempty String IDs/names/strength/limitation text; one recognized catalog weapon ID per row; finite integral starting_scrap within0..1,000,000 (not bool/string); default_id must be exactly `rivet`, with that row present and matching factory Rivet plus catalog starting_coins. Invalid registry fails startup validation, not a silently substituted kit.
- Existing catalog/balance/encounter/affinity definitions and ordering remain byte-identical. No selection RNG draws. Alternate owned weapon tags intentionally alter later existing weighted shop choices; do not claim same offers across different kits. Same version+mode+seed+kit is the deterministic input tuple.

## Draft selection, start and lifecycle
- Main owns a title-only `selected_loadout_id` draft, initially `rivet`; RunSession owns `starting_loadout_id`, the successful run's immutable starter identity. This identity records origin, not current equipment and grants no passive effects.
- Title displays current mode, seed and selected kit together. Selection survives title refresh, mode switch, field guide/display settings and return to title during this process. It is not saved across process restart.
- Choosing a different kit uses a presentation-only title render, not cleanup-bearing `_title()`, and changes only the draft, title generation and presentation; it does not create/equip/sell/refund anything, touch current build/stats/transients or draw RNG. Re-selecting current kit is a no-op. Returning to title keeps the last selected draft; it does not infer a kit from acquired/sold/reordered equipment.
- Each title render has a monotonically advancing generation. New `select_starting_loadout` and `start_loadout` intents require actual integer current generation, recognized String ID, state=title; selection ID is the requested draft, start ID must equal the displayed/current selected draft. New start additionally requires actual integer seed. Stale/wrong-type/unknown/state-mismatched requests reject atomically before cleanup, coins or RNG changes.
- `_start_run(seed, kit_id="rivet")` retains the old one-argument Rivet path for existing direct callers/automation. An invalid explicitly supplied kit rejects before any cleanup. New title starts supply the selected ID explicitly. Legacy two-argument `show_title` and legacy `start` intent remain Rivet-compatible; only the new context produces the new guarded actions.
- Successful start snapshots the validated kit ID and initializes exactly one weapon clock0.0, normal100 HP/base movement, LV1/XP0/kills0/time0, empty modules/upgrades/hold/offers/effects and all existing reset behavior. Selected kit is applied before stats/effects/rig initialization; no intermediate visible Rivet state for alternatives.
- Same-seed retry and new-seed retry use the completed run's starter snapshot, not current equipment or mutable title draft. New seed is exactly old+1; retry retains old seed. Existing mode is retained. Returning to title and selecting a different kit intentionally changes only the next run.
- Stage transitions, ordinary rewards/level choices/salvage/shops/holds/reorder/sale/replacement do not modify starting_loadout_id or regrant starting equipment/currency. Starting gear is ordinary owned gear and contributes to inventory, tags/affinity and existing purchase/sale limits normally.
