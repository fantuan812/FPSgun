## 2. Eligibility and deterministic identity
Eligible recipient: present Dictionary with finite hp/max_hp, max_hp>0, 0<hp<max_hp, boss==false, parent_id==-1, kind!=stitch_drone, id!=source.id. Source must be present living stitch_drone. ## 3. Unified phase ordering (not enemy-array order)
Existing primary firing, mortar/hazards, each ordinary AI/movement/clamp, spawn_requests, hostile and friendly projectile updates, deaths/kill events and pickup events retain their mutual order.

Support movement occurs in the normal enemy loop: in move state seek desired player distance using ranged +/-30 deadband; warning and recover stationary. Clamp/sprite/actor observation continue as normal. It never produces an offensive AI event. Existing contact convention remains: move contact hurts, warning/recover contact-safe. Only support-specific branch differs.

Phase A occurs once AFTER all existing enemy AI/movement/clamp and queued child spawning, BEFORE hostile projectiles. All sources/targets use these current post-clamp positions. Traverse living support sources in ascending ID. All support sources snapshot membership at Phase A; later additions cannot acquire this step. Main mode spawn occurs before CombatRuntime.step and is included; existing queued summons are parented and ineligible. No new extra spawn requests.

For an existing warning, first validate recipient/source/range and source HP witness; cancel if invalid. Otherwise decrement warning_left by dt once, and mark due if <=0. For a nonwarning source, decrement cooldown once; if <=0 attempt acquisition. If acquired set warning_left=1.2 and snapshot source HP, and DO NOT subtract this step's dt from newly started warning. If none eligible set cooldown=retry1s, remain move. No looping/catch-up, at most one completion per source per step.

Existing damage before acquisition (primary firing, mortars, hazards, hostile contact proc during older AI) is already reflected in start HP and does not retroactively interrupt. Existing warning source HP is compared to its original snapshot, so those same early paths DO interrupt an ongoing channel. Late projectile/proc loss after acquisition interrupts even in acquisition's own step. This discrete phase boundary is intentional, not a continuous time/subframe claim.

Phase B occurs once AFTER all existing pickup/proc handling and flash aging, BEFORE final focus prune. If session.state!='playing', do not heal, cancel any support channel and hide its tether. Re-find source and target by ID; membership alone is insufficient: both must hp>0 even if a late kill/proc left a dead Dictionary not yet removed. Recheck eligibility, current endpoint distance, and source HP witness for EVERY active warning, including not-yet-due channels. Invalid cancels immediately. A target reaching full HP invalidates/cancels rather than reserving repair. Valid due intents resolve in ascending source ID; each rechecks after previous repair. Apply min(max_hp,hp+10), no other mutations of target attack/status/reward/maxHP. If earlier source fills target, later one cancels, no stored charge.

Do NOT repeat or flush the old death loop after repair: existing reward/drop timing remains. Dead-at-end actors never resurrect. Pickup/kill procs that kill source/target in this step beat repair. Terminal early returns in older runtime paths likewise prevent Phase B healing. Direct invocation on a nonplaying frame may not execute new support phases/heals, without asserting changes to unrelated legacy direct-step behavior.

## 4. Cancellation/cooldown/large dt
Damage interruption is source.hp < channel_start_hp, not hit/VFX count. The source cannot receive any new healing; baseline inventory finds no other enemy HP increase. No signal hooks or damage rewrites necessary. Target nonlethal loss alone does not interrupt. Zero resolved damage, chill/slow alone and pure pull/push do not damage-interrupt; displacement may independently fail range at Phase A or B. No continuous path-crossing test between those observations.

Success or cancellation at Phase A/B enters recover for .7s and sets cooldown5s at that exact phase. No subtraction from newly set cooldown/recovery until next tick. Recovery countdown and cooldown advance once on later Phase A ticks; once recovery expires movement resumes on the next normal movement pass. Cooldown is measured from actual success/cancel, not acquisition. Cancel at A cannot reacquire that tick. Large dt can expire a pre-existing warning once but cannot begin a second channel or catch up cooldown during the same tick. Valid dt is existing simulation nonnegative finite input; focused tests include0, exact1.2 expiration and large dt, without relaxing generic runtime contracts.

## 8. Explicit implementation interface/invariants and pre-freeze clarifications
The earlier sections describe normative gameplay. These clarifications close initial independent proposal review gaps without changing any production file.

World invariant: actual `_spawn_kind` increments next_enemy_id and yields unique positive integer IDs. New support policy rejects invalid/duplicate identity sets fail-closed (empty selection/no repair), rather than using array order to arbitrate a malformed world. It must not mutate valid old actors or general runtime identity rules.

Proposed `EnemySupport` RefCounted static API (freeze before independent scripts bind it):
- `validate_entry(entry:Dictionary)->Array`: new support-only schema diagnostics.
- `select_target(source:Dictionary,enemies:Array)->int`: eligible best target ID, or -1; pure/no mutation/no RNG.
- `can_repair(source:Dictionary,target:Dictionary)->bool`: pure eligibility/range/source snapshot witness; target must correspond to stored ID when channel active. No state change/heal.
- `advance(enemies:Array,dt:float,playing:bool)->Array`: Phase A, mutate only support timer/channel fields; returns due tickets in ascending source-ID order. No HP writes, callbacks or presentation effects. Existing nonplaying input returns [] with support channels canceled, no timer advancement.
- `settle(enemies:Array,due_tickets:Array,playing:bool)->Array`: Phase B, revalidates ALL active warnings and due tickets, applies actual HP increases only for valid due sources; returns detached bounded transition records `{source_id,target_id,kind,amount,source_pos,target_pos}` where kind is `complete` or `cancel`. No VFX/actor calls; runtime consumes transitions. A cancel generated by advance must be carried to settle without duplicates in an explicit transient per-source flag. Actual state fields all per-actor: `support_target_id`, `support_start_hp`, `support_due`, `support_cancel_pending`; new channel/recover use existing ai_state/warning_left/recover_left/cooldown_left.

Support EnemyAI branch only moves an existing move state and returns []; it does NOT decrement cooldown/recovery/warning there. All three timers for this behavior are owned by Phase A so no double dt. Other seven kinds remain on their existing exact tick path. Transition after Phase A must be reflected in actor presentation without advancing another timer; a just-acquired source already moved once earlier in that step.

A real repair sets target.anim_hp = target.hp AFTER the HP increase, and does not call actor.trigger/reset animation. This restores the next-step hurt baseline but preserves any hurt/death state already triggered by existing logic. No repair occurs on hp<=0. Exact native/fixture checks distinguish repairing HP from faking a hurt animation.

Normal Arena support pool filter is activated only for a validated pool containing support entries. If filtering leaves no eligible candidates, return {} without consuming a kind draw, after the original position draws/position eligibility have already occurred. No fallback kind fabricated, no reroll. Current shipped wave4 always retains its three old choices. Malformed empty/unknown pools remain rejected by existing config validation before run; new filter also fails closed if directly supplied malformed input (no kind draw, no spawn), without claiming legacy malformed configuration was supported. No-support valid pool code path remains exact old random selection, no extra RNG call.

Terminal cancellation erases target/snapshot/pending channel state and hides tether without a completion or cancellation burst (no result-screen transient). Source death does likewise; dead source cannot enter recover or create a new cancel effect. Living cancellation produces at most one transition per source per channel. Pause differs: retain frozen state/timers, no new transition until playing resumes. Acquired/source HP witness uses actual floating comparison <, no epsilon that could ignore small positive loss.

## 9. Interface tightening after first C1 static review (integrated C2 definitions)
- Pause/shop/upgrade: the caller does not invoke support advance/settle at all, so channels and timers remain frozen. `playing=false` at the support API specifically denotes terminal/reset disposal, NOT pause. Direct nonplaying runtime invocation must distinguish paused state (no support call) from terminal (cancel without visual). No generic `state!='playing' => false-call` that would erase pause state.
- Runtime positions must be finite Vector2; required hp/max_hp/source start HP and active timers must be finite int/float, never bool, with positive max_hp and positive configured channel/cooldown/retry spans. Remaining warning_left/cooldown_left/recover_left are finite numbers that MAY be negative after a large dt subtraction; <=0 is expiration, not malformed input. Runtime must not discard a valid due channel merely because its remaining timer is negative. Input dt must be finite and >=0; invalid dt yields no progression or repair, without changing unrelated legacy simulation rules. Source kind AND behavior must be stitch_drone AND support_repair. Exclude recipient with EITHER kind stitch_drone OR behavior support_repair, so malformed identity cannot create source regeneration. Malformed inputs return no selection/repair and clear invalid active channel without an effect rather than silently casting. IDs must be unique positive actual int (bool excluded). Data validators reject invalid config before runtime; runtime safeguards do not expand supported config.
- Phase A sees unified clamped positions. Phase B uses actual current positions, including any later pull/push, without an additional clamp; do not move actors to make repair eligible. Both endpoints must still be finite Vector2.
- `support_cancel_pending` is a detached Dictionary, empty when absent; when A cancels a living source it stores exactly the final public transition fields `{source_id:int,target_id:int,kind:"cancel",amount:0.0,source_pos:Vector2,target_pos:Vector2}` before clearing target/witness/due/token. Endpoint is the actual target position if a finite present target can be resolved, otherwise the last valid Vector2 stored as `support_target_pos`; source position must be finite or no visual record. At channel entry and each valid A/B observation refresh support_target_pos. B drains at most one pending record once, clears it regardless of whether it is emitted, and emits only if source is still living and playing. Death/terminal clears pending without a burst. A cancellation and B cancellation of the same channel cannot both emit.
- The frozen output of advance is `Array of due tickets`: each `{source_id:int,channel_token:RefCounted}`. Every successful acquisition creates a fresh empty RefCounted token stored as support_channel_token; this is a private ephemeral identity, not an enemy reference, RNG value, public save field or presentation record. Reset/death/cancel/success clears it. Different channels and runs cannot reuse object identity. No strong reference to an enemy or stream is kept by that empty token.
- `settle(enemies:Array,due_tickets:Array,playing:bool)` requires source currently warning, support_due actual bool true, warning_left <=0, and a valid supplied ticket whose source_id matches and channel_token is the IDENTICAL current object. Unknown/malformed/duplicate tickets cannot add a heal; duplicate valid ticket is processed once. A fabricated fresh token, earlier channel token, or already-used token is rejected. Clear due/token on success before another call can heal. A valid due warning with no matching ticket is left pending and does not heal; policy tests exercise this explicitly. Real runtime passes only this step's advance output and discards after settle. Sort accepted current source identities ascending. This avoids claiming stale numeric IDs alone can identify a channel.
- Transition records returned from settle contain only value fields (IDs, kind, amount, Vector2); no internal token or actor reference escapes into VFX. Both API purity tests and stale-ticket negative controls are required before runtime integration evidence. `select_target` and `can_repair` remain pure; advance/settle explicitly mutate only authorized support state and heal/anim_hp fields.

## 10. Testable runtime dictionary schema
Policy path is exactly `res://scripts/gameplay/enemy_support.gd`.

All actors supplied to policy have `id:int>0`, `kind:String`, `behavior:String`, `boss:bool`, `parent_id:int`, `pos:Vector2` finite, `hp:number` finite, `max_hp:number>0` finite. An ordinary target needs only these fields plus `anim_hp:number` finite for successful heal; no Sprite/Node or actor-director reference is required in the pure-policy fixture. hp<=0 is a valid dead actor, not malformed numeric data. parent_id -1 means ordinary; other values are ineligible recipients. Source identity is exactly stitch_drone/support_repair/nonboss/parent_id -1.

A support source additionally has the six configured support fields from section1, plus `ai_state:String` in move/warning/recover, `cooldown_left:number`, `warning_left:number`, `recover_left:number` (all finite remaining timers, negatives allowed), `support_target_id:int`, `support_start_hp:number`, `support_due:bool`, `support_cancel_pending:Dictionary`, `support_target_pos:Vector2` finite, and `support_channel_token` null or RefCounted. New source initialization is target_id=-1/start_hp=0/due=false/pending={}/target_pos=its spawn pos/token=null, move/cooldown=.8/warning=0/recover=0. No unmentioned sprite/aim/attack/phase field is required by the policy; real spawn retains those existing fields for its renderer/AI integration.

Warning requires positive target ID, positive finite start_hp and a nonnull RefCounted token; nonwarning state carries sentinel cleared target/witness/due/token (pending cancel record may remain until B drains). `can_repair` specifically requires this active warning schema and the stored target ID, not merely an arbitrary source/target pair; `select_target` handles acquisition with nonwarning source. A manually supplied source must use the listed fields, rather than relying on production initializer to fill missing data. Numeric diagnostics/fail-closed behavior cannot convert bool to1 or a fractional ID to an int.

A successful heal may update only target hp and anim_hp, source lifecycle fields, and return value records; actor dictionaries unrelated to selected support/recipient remain equal. The token object is never a source/target dictionary. No extra userdata dictionaries, RNG, timers or generic action callbacks are required by these policy APIs.


## 11. Existing versus injected late-event damage scope correction
C3 retains all gameplay parameters/API/ordering from reviewed C2 but corrects an evidence premise: current effects.gd kill only emits energy orb or PLAYER healing; pickup grants charge or creates a mine. There is no existing kill-chain or pickup-immediate-enemy-damage module. A pickup-created mine damages only at a later advance_hazards call after its maturity, not immediately during that pickup. Earlier references to late kill/pickup lethal cases mean defensive event-seam controls, not a claim those production modules currently exist.

Mandatory runtime proof has two explicitly separate classes: (A) actual existing weapons and actual configured effects paths from DAMAGE_PATH_INVENTORY, including hit-chain/phase/feedback and mature mine; (B) fault-injected late-event controls using a clearly named test-only engine subclass that preserves super.process and injects an existing chain/thorns damage command ONLY when real Runtime emits kill or pickup. Class B still exercises real EffectRuntime HP subtraction and final support settlement, but is NOT an ordinary current build interaction, new production proc, or evidence that today's pickups instantly damage enemies. No production effects.gd behavior is added. Keep event/raw reports and public claims separate.

Presence plus hp>0 checks, no second death flush and after-pickup settlement remain prudent exact contract requirements. Source/target lethal controls using actual primary and existing effects are natural-game controls; late event fault injection extends adversarial ordering coverage without implying a naturally reachable current module combination.
